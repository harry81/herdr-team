# TIL: 개발자 문서에서 전환율 중심 README UX로 (2026-09-04)

`herdr-team` README를 기술 레퍼런스에서 일반 사용자 랜딩 페이지로 전면 개편하며
정리한 README UX 설계 이론.

## 1. 정보 구조(IA): Hero → Why → 30초 → 부록

- 방문자는 10초 안에 이탈을 결정한다. 순서를 **가치 약속(Hero) → 공감(Why) →
  행동(Quick Start) → 증거/참고(Advanced 부록)** 로 강제한다.
- 기존 기술 내용(트리, 옵션, 프로토콜)은 삭제하지 않고 `## Advanced` 이하로
  격리한다. "내용 무손실 + 스크롤 위치 이동"이 리라이트의 안전 조건이다.
- `## Quick Start`, `## Advanced` 같은 랜딩 앵커를 고정 헤딩으로 두면
  외부 링크·테스트 가드레일 모두 안정된다. 헤딩은 곧 API다.

## 2. Hero 섹션의 3요소

- **L1 = 제품명 한 줄** (`# herdr-team`): 검색·렌더링·테스트의 기준점.
- **1줄 가치 훅**: 기능 나열이 아니라 결과 약속
  ("터미널이 4분할 AI 팀으로 변한다"). 기술어는 뒤로 미룬다.
- **ASCII 다이어그램**: 4-pane 협업을 한눈에. 폭 ≤78자(모바일·좁은 터미널 깨짐 방지),
  `+ - |` ASCII만 사용(박스 드로잉 문자는 폰트별 너비가 달라 깨진다).
  다이어그램 아래에 레거시·한국어 안내를 접어두어 Hero를 오염시키지 않는다.

## 3. Why 섹션은 페르소나 × 프리셋 매핑

- `app/biz/dev` 프리셋을 사양 표로만 두지 말고, 각 프리셋에 인물 서사를 붙인다
  (주말 사이드 프로젝트 / 코딩 없는 사장님 / TDD 개발팀).
- "누가, 언제, 무엇을 얻는가"가 한 블록에 들어간다. 독자는 자신의 블록에서
  전환되고, 나머지는 스킵한다 — 스킵 가능하게 쓰는 것이 핵심이다.

## 4. 30초 Quick Start의 플랫폼 분기

- Windows는 "ZIP → 압축해제 → 더블클릭" 3단계로, 터미널 언급 자체를 금지한다
  ("터미널 0회"를 명시하면 비개발자의 두려움이 제거된다).
- Linux/macOS는 `curl | bash → hts` 한 줄을 최상단에. 단, 파이프 설치의 전제
  (`HERDR_TEAM_REPO_URL`)를 숨기지 않고 코드에 그대로 노출한다 —
  복사-붙여넣기 실패가 전환율에 가장 치명적이기 때문이다.
- 대안 경로(git clone)는 한 줄 괄호로만 둔다. 주 경로가 둘 되면 둘 다 안 눌린다.

## 5. 테스트로 랜딩 구조를 고정하는 법

- 마케팅 카피는 자주 바뀌지만 IA는 바뀌면 안 된다. 테스트에는 카피가 아니라
  구조를 단언한다: L1 정확 일치, `## Quick Start`·`## Advanced` 존재,
  `start-team.bat`·`curl`·`hts` 토큰 존재.
- 내용 리라이트 후에도 가드레일이 전부 통과하면 "구조 보존 + 내용 개선"이
  증명된다. 이것이 문서 작업에서의 TDD Red→Green이다.
